# Plumit · Бухгалтерия проектов

Веб- и мобильное приложение для учёта денег по проектам студии вместо Excel. Работает на Firebase: вход через Firebase Auth, данные в Firestore, сайт на Firebase Hosting. Своего сервера не нужно.

Мобильная версия — PWA: открываете сайт на телефоне и добавляете на главный экран. Приложение открывается без сети, а операции, внесённые офлайн, отправятся, когда появится связь. Данные обновляются у всех в реальном времени.

## Что умеет

| Было в Excel | Стало в приложении |
|---|---|
| Лист на проект, блоки по месяцам | **Проекты** → карточка проекта с вкладками |
| «Итерация» + столбцы с долями разработчиков | **Итерации**: пункт работ, стоимость для клиента, кто сколько получает; статус (в плане / в работе / сдано / отменено). Кнопки «Как в прошлой» и «Поровну» |
| Строки «Поступления / Платежи / Налоги» по дням | **Операции**: поступление (аванс), выплата, расход, налог/взносы, штраф, перевод внутри команды. Вкладка «По дням» показывает ту же таблицу, что в Excel |
| «Стоимость работ / Выплачено / Осталось выплатить» | Считается автоматически: начислено по итерациям − штрафы − выплачено. Кнопка «Выплатить» подставляет остаток |
| «Расходы: Точка, Взносы, Сервера» | Расходы со статьями, можно без привязки к проекту |
| «Журнал расходов» текстом | Переводы между людьми + комментарии к любой операции |
| «Чистые» | Чистые (план) = стоимость проекта − начислено команде − расходы − налоги |

Ещё: сводка по всем проектам с графиком движения денег за 12 месяцев, долг перед каждым участником, выгрузка в CSV (открывается в Excel), светлая/тёмная тема, доступ по email с правами «администратор» или «только просмотр».

## Роли

| Роль | Что видит | Что может |
|---|---|---|
| **Администратор** | всё | вносить и править данные, выдавать доступ |
| **Только просмотр** | всё | только смотреть |
| **Сотрудник** | только свои начисления по проектам, выплаты, штрафы и свои документы | только смотреть |

Сотрудник привязан к участнику команды: **Команда → человек → Личный кабинет → email**. Его выписка (`statements/{id}`) пересчитывается приложением администратора после каждого изменения данных. Правила Firestore не отдают сотруднику ни проекты, ни операции, ни чужие выписки.

**Документы** (договоры, акты, NDA, счета) — ссылки на файлы в Google Диске или Яндекс Диске: **Команда → человек → Документы**. Откройте доступ к файлу по ссылке, чтобы сотрудник смог его открыть.

## Накопительные счета

Раздел **Счета** (на телефоне — **Ещё → Накопительные счета**): остаток, ставка, капитализация, пополнения, снятия, смена ставки и проценты от банка. Приложение считает, сколько набежало процентов с последнего начисления (по дням: остаток × ставка ÷ 365), и прогноз на месяц и год. Когда банк начислит проценты, запишите их кнопкой «Проценты от банка» — расчёт начнётся заново.

## Отчёты

Раздел **Отчёты** (на телефоне — **Ещё → Отчёты**): период (месяц, квартал, год, всё время или свой диапазон) и проект. Поступления, выплаты команде, расходы, налоги и прибыль по месяцам, по проектам, по статьям расходов и по людям.

**Выгрузить в Excel** — книга `.xlsx`: лист «Сводка» и отдельный лист на каждый проект в привычном виде — общие подсчёты выплат (стоимость работ / выплачено / осталось), итерации с долями, таблицы по дням за каждый месяц («Число · ВСЕГО · 1…31») и журнал операций. Итоги в файле — формулы Excel. Библиотека ExcelJS загружается только при выгрузке.

## Журнал изменений

Раздел **Журнал** (на телефоне — **Ещё → Журнал изменений**): кто и когда добавил, изменил или удалил операцию, проект, итерацию, участника, документ, счёт или доступ. Для изменений показано «было → стало» по каждому полю, для удалений — что было удалено. Запись в журнал (`audit`) пишется в одном батче с самим изменением, время ставит сервер; правила не дают подделать автора или время, изменить или удалить запись.

## Импорт данных

**Настройки → Импорт данных** принимает файл `.json` (формат описан в `src/lib/importer.js`). Перед записью показывается, что будет добавлено, и ошибки в файле. Участники с таким же именем не дублируются.

## Настройка Firebase (один раз)

1. Создайте проект в [консоли Firebase](https://console.firebase.google.com). Google Analytics не нужен.
2. **Authentication → Начать → Sign-in method**: включите **Google** и **Email/Password**.
3. **Firestore Database → Создать базу** в рабочем режиме (production). Регион — `europe-west` (ближе к России).
4. Конфигурация веб-приложения проекта `plumit-buh` уже лежит в `.env`, а привязка к проекту — в `.firebaserc`. Для другого проекта: **Настройки проекта → Ваши приложения → Веб (`</>`)**, значения — в `.env.local` по образцу `.env.example`, ID проекта — в `.firebaserc`.
5. Установите зависимости и войдите в Firebase CLI:
   ```bash
   npm install
   npx firebase login
   ```
6. Опубликуйте правила и сайт:
   ```bash
   npm run deploy
   ```
   Сайт будет доступен по адресу `https://<проект>.web.app`. Свой домен (например, `buh.plumit.ru`) подключается в разделе **Hosting → Добавить собственный домен**. Этот домен также нужно добавить в **Authentication → Settings → Authorized domains**.
7. **Первый администратор.** Откройте сайт и войдите через Google или зарегистрируйтесь по почте. Затем в консоли: **Firestore → Начать коллекцию** `access` → ID документа = ваш email **в нижнем регистре** → поле `role` (string) = `admin`. Страница откроется сама.

   Остальных людей добавляйте прямо в приложении: **Настройки → Доступ**.
8. Чтобы посмотреть приложение на примере, в пустой базе есть кнопка **Настройки → Загрузить демо-данные** (вымышленные проекты).

## Автовыкладка (GitHub Actions)

При каждом push в ветку по умолчанию GitHub прогоняет тесты (расчёты и правила безопасности) и выкладывает сайт и правила Firestore в Firebase. Pull request'ы и другие ветки только тестируются. Ход выкладки — во вкладке **Actions** репозитория.

Вход в Google — без ключей, через Workload Identity Federation: GitHub получает от Google временный пропуск при каждом запуске, и только для этого репозитория. Настройка — один раз:

1. Откройте [Google Cloud Shell](https://shell.cloud.google.com/?show=terminal) под аккаунтом владельца проекта `plumit-buh`.
2. Выполните:
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/F31-EXE/plumit-buh/claude/epic-gates-eun66q/scripts/setup-github-deploy.sh)
   ```
   Скрипт включит нужные API, создаст сервисный аккаунт `github-deploy` с ролями **Firebase Admin** и **Service Usage Consumer** и разрешит репозиторию `F31-EXE/plumit-buh` входить от его имени. Повторный запуск безопасен.
3. **Actions → «Тесты и выкладка» → Run workflow** — первая выкладка.

Если репозиторий переедет или переименуется, поправьте `REPO` в `scripts/setup-github-deploy.sh` и запустите скрипт снова.

## Разработка

```bash
npm run dev:emulators   # локально на эмуляторах Firebase, без настоящего проекта (нужна Java)
npm run dev             # локально, но с настоящим проектом из .env.local
npm test                # тесты расчётов
npm run test:rules      # тесты правил безопасности на эмуляторе Firestore (нужна Java)
```

На эмуляторах письма не отправляются: ссылку подтверждения почты печатает в консоль эмулятор Auth. Доступ выдаётся так же, как в п. 7, через [Emulator UI](http://127.0.0.1:4000) или REST.

## Безопасность

Данные защищает файл `firestore.rules`:
- читать могут только пользователи с подтверждённой почтой, чей email есть в коллекции `access`;
- изменять данные может только роль `admin`; каждое поле проверяется по типу и допустимым значениям;
- администратор не может случайно удалить себя или понизить себе права.

Ключи в `.env.local` (`apiKey` и др.) не секретные: они попадают в код сайта, а доступ ограничивают правила.

**Резервные копии:** включите в консоли **Firestore → Disaster recovery → Backups** (ежедневные копии) или периодически выгружайте CSV из приложения.

## Структура данных (Firestore)

Суммы хранятся в копейках (целые числа).

| Коллекция | Поля |
|---|---|
| `access/{email}` | `role` (`admin` / `viewer` / `employee`), `name`, `member_id` (для сотрудника) |
| `members` | `name`, `role`, `active` |
| `projects` | `name`, `client`, `budget`, `status`, `start_date`, `notes`, `member_ids[]` |
| `iterations` | `project_id`, `title`, `price`, `status`, `date`, `sort`, `shares {memberId: сумма}` |
| `operations` | `type`, `date`, `amount`, `project_id`, `member_id`, `from_member_id`, `category`, `comment`, `is_advance`, `created_by` |
| `statements/{memberId}` | выписка сотрудника — пересчитывается автоматически |
| `documents` | `member_id`, `title`, `kind`, `url`, `date`, `notes` |
| `accounts` | `name`, `bank`, `rate` (% годовых), `capitalization`, `opened`, `archived` |
| `audit` | `at` (время сервера), `user`, `action`, `entity`, `entity_id`, `label`, `changes`, `snapshot` |
| `account_ops` | `account_id`, `type` (`deposit` / `withdraw` / `interest` / `rate`), `date`, `amount` или `rate`, `comment` |

Все расчёты (касса, долг команде, «чистые») делаются на клиенте в `src/lib/finance.js`. Для студии это сотни или тысячи документов, бесплатного тарифа Spark хватает с запасом.

## Фирменный стиль

Все цвета и шрифт задаются токенами в начале `src/styles.css` (`--accent`, `--bg`, `--font` и т.д.), отдельно для светлой и тёмной темы. Тему переключает кнопка ☀/☾ (в боковой панели, на телефоне — в шапке): новая тема расходится кругом от кнопки. В «Настройках» можно вернуть режим «Как в системе».

Логотип — `public/logo.png`; иконки приложения (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`, `favicon.png`) сделаны из него.

Пасхалка: три быстрых нажатия на логотип открывают `public/media/egg.mp4` со звуком.

Если понадобятся приложения в App Store / Google Play, тот же код можно упаковать через Capacitor.
